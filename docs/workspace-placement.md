# Workspace placement compatibility

Worktree creation uses the public Paseo 0.8.0 SDK `workspaces.create` with a worktree `branch-off` source. Local creation keeps the original project root; creating a Worktree passes the exact selected ref. Remote `main` maps to `refs/remotes/origin/main`, and `main (local)` maps to `refs/heads/main`. No branch name or worktree slug is supplied. The session prompt, or optional title for a Terminal, is provided through `firstAgentContext.prompt` for Paseo's normal naming behavior.

Git metadata is a narrow exception to [ADR-0002](adr/0002-measure-rendering-before-a-rust-rewrite.md)'s public-SDK rule: the pinned SDK and CLI do not expose checkout status or branch suggestions. `src/paseo/worktree.ts` alone imports the package's explicitly exported `internal/daemon-client` entry. The gateway owns a separate lazy connection for those two read operations, shares the resolved target and authentication, closes failed connections and its owned socket, and exposes an injectable narrow factory for gateway tests. Workspace/resource creation continues through the public SDK. No daemon change is required.

The default Base ref uses checkout status `baseRef`, not the current feature branch. For an owned worktree project root, the main checkout's status supplies the repository default. Remote and local twins are always distinguishable; repositories without branch refs (including unborn repositories) offer Local only. Discovery failures are visible and retryable; they do not silently switch creation to Local.

A live 0.8.0 probe showed that `checkoutRefresh` only refreshes metadata: it returned success with stale remote refs and even an unreachable origin. Deck therefore never uses it as evidence of a fetch. The user-approved compatibility path performs `git fetch --prune origin +refs/heads/<branch>:refs/remotes/origin/<branch>` before workspace creation, so a deleted or unavailable remote branch fails instead of using a stale local tracking ref. The command uses argument arrays, a 60-second timeout, and disabled interactive credential prompts. Errors pass through the existing gateway redaction boundary.

Local execution requires no explicit `--host`, no inherited `PASEO_HOST`, fresh CLI daemon status showing a running local daemon with a live PID, and the same listen target as the connected gateway. Even explicit `--host localhost:port` is unsupported for remote-base refresh because it may address a tunnel or another filesystem namespace. Such connections can still create from explicit local base refs through the daemon. Remote refresh errors retain all composer inputs and create no workspace.

Automated coverage uses the approved public application-controller/gateway boundary and the TUI input/render boundary. It verifies defaults, exact refs, both initial resource kinds, picker navigation, discovery/fetch failure recovery, unsupported repositories, local execution guards, and owned socket cleanup. Render captures use deterministic fixtures; they demonstrate controls and visibility, not daemon or provider execution. Semantic generated branch names require provider execution and are not asserted by these tests.
